# StudyAI QA Sample Portfolio

Recruiter-facing sample QA artifacts for StudyAI, an AI study companion described as a React frontend with a Flask backend and AI-assisted summaries, flashcards, quizzes, and progress features.

## Included
- `test-cases/StudyAI_Test_Cases.xlsx` — 23 planned functional, negative, resilience, API, and security-oriented test cases.
- `bug-reports/StudyAI_Sample_Bug_Reports.pdf` — formatted report with five hypothetical defect reports.
- `bug-reports/StudyAI_Sample_Bug_Reports.md` — editable source for the bug reports.
- `automation/` — Java + Selenium + TestNG + Maven UI smoke-test starter.

## Evidence and honesty
- Test cases are marked **Not Run**.
- Bug reports are explicitly **Sample / Not verified** and contain no invented actual observations.
- The automation suite has not been executed against the actual StudyAI app in this environment. It is an executable starter suite, not proof of passing tests.
- The UI smoke tests intentionally avoid app-specific login selectors because the live StudyAI DOM and deployed URL have not been inspected. They check basic route rendering and obvious navigation issues. Add feature-specific locators only after validating the actual app DOM.

## Run the UI smoke tests
Prerequisites: Java 17+, Maven 3.9+, Google Chrome/Chromium, and the StudyAI frontend running locally or at an authorized test URL.

From the `automation` directory:

```bash
mvn test
```

Default base URL is `http://localhost:3000`. To use a different environment:

```bash
mvn -DbaseUrl=https://YOUR-AUTHORIZED-STUDYAI-TEST-URL test
```

For a visible browser, set `HEADLESS=false` in the environment before running. Selenium Manager may download a compatible driver; network access and browser compatibility may be required.

## Recommended next steps before sending to recruiter
1. Run the test suite against a known StudyAI build and save the Maven/Surefire output.
2. Update the test case workbook's Actual Result, Status, and Evidence fields from observed results only.
3. Reproduce each proposed defect before converting it into a confirmed bug report; otherwise keep it labeled as a test idea.
4. Replace the environment placeholders with non-sensitive build/browser details.
5. Include a screenshot or report only after it has been generated by a real run. Do not include API keys, tokens, private user data, or unredacted logs.
